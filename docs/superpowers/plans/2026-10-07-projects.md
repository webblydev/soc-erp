# Projects Implementation Plan

> Steps use checkbox (`- [ ]`) syntax for tracking. Each task ends with its tests passing, Pint run and per-file commits.

**Goal:** Build the Projects module (docs/04 without the 05–08 parts): project master, services and contract value, contract with schedule and amendments, team, tasks with templates, checklists, comments and time, approvals tracking, the conversion project step, and the CRM / HRM hooks.

**Architecture:** A new `app/Modules/Projects` module that copies the CRM / HRM structure: Auditable models, Action classes that authorize + validate + write in a transaction, class-based Livewire screens over BlatUI components, lookups on the shared Master Data screen. Other modules get `CreateProject` (CRM conversion), the project events, `ProjectCompletionChecks` and the `allowsBilling()` / `allowsCosting()` helpers.

**Tech Stack:** Laravel 13 / PHP 8.4, Livewire 4 (class components, `Route::livewire`), BlatUI (`x-ui.*`), Tailwind v4, Pest 4 on in-memory SQLite, brick/money.

**Spec:** `docs/superpowers/specs/2026-10-07-projects-design.md` (decisions P1–P25). Read it with docs/04 before each task.

## Global Constraints

- Rules in `AGENTS.md` and `.ai/rules/modules.md`: module code in `app/Modules/Projects/{Models,Livewire,Policies,Services,Actions,Events,Listeners,Jobs,Notifications,Concerns,Contracts}`; migrations in `database/migrations/projects/`; seeders in `database/seeders/Projects/`; routes in `routes/modules/projects.php` (required from `routes/web.php`); business logic only in Actions; every write Action uses `DB::transaction()`.
- UI only with BlatUI `x-ui.*` components and the existing `x-shell.*` shell components, light mode only, the strict mobile rules.
- Route keys: `{project:project_number}`, `{task:task_number}`; templates, approvals and amendments use ids.
- Money with `App\Support\Money` / brick; amounts `DECIMAL(18,2)`, rates and quantities `DECIMAL(18,4)`.
- Commits: one commit per file-level change group, mid-length message, no AI co-author line (AGENTS.md).
- Run `vendor/bin/pint --dirty --format agent` before each commit that touches PHP.
- Tests: `php artisan test --compact tests/Feature/Projects/<File>.php`. Never run browser tests.
- No new composer / npm dependencies.

## Review Focus

1. **Scope leaks.** An engineer must not reach another project's page, tasks or approvals by URL, by Livewire action ids (team member, schedule line, checklist item, comment) or through the tasks board. Pinned in `ProjectAccessTest` and `TaskAccessTest`.
2. **Signed contract lock.** Services, deed amount and schedule totals cannot be changed around the lock through `UpdateProject`, `SaveProjectServices` or `SavePaymentSchedule` once signed. Pinned in `ContractTest`.
3. **Conversion atomicity.** A failing project step must leave no customer, no project and the lead unchanged (CRM-AC-06). Pinned in `ConvertWithProjectTest`.
4. **Task status rules.** The assignee cannot approve their own review; refused moves on the board must not change the task. Pinned in `TaskStatusTest`.
